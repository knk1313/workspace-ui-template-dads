# グラフの選び方（ダッシュボードデザインの実践ガイドブック要約）

出典: デジタル庁「ダッシュボードデザインの実践ガイドブック」（2026年3月31日版）。本テンプレートの `src/components/charts/` はこの要約に従って設計している。

## 画面構成

1. **左上から右下へ、全体 → 部分**。左上に全体を端的に示す指標（KPI）、右下に最も詳細な情報（一覧表）。左上は背景色で強調する（`StatCard` の `highlight`）。
2. フィルターは上または左に置き、影響を受ける情報はその下 / 右に置く。
3. 情報は階層化し、適切な情報量にする。複雑な操作を要求しない。
4. 数量単体では判断できない指標には、目標値・平均・前年・前年比など**比較対象を併記**する。

## グラフの選び方

| 伝えたいこと | 使うもの | テンプレートのコンポーネント |
| --- | --- | --- |
| 判断や行動を左右する値 | 指標（数値 + 前期比 + 注記） | `StatCard` |
| 時間変化・傾向 | 折れ線（横軸は必ず時間。データ点に図形。系列名は線の近く） | `LineChart` |
| 数量の比較 | 棒（まず棒を検討。集合棒・積み上げ棒） | `BarChart` |
| 数量と構成比の時間変化 | 積み上げ面（構成比のみなら 100% 積み上げ） | `AreaChart` |
| 構成比（総量が明らかで、コンパクトに伝える場合だけ） | 円 / ドーナツ。多くの場合は棒の方が正確 | `DonutChart` |
| 正確な値の参照、データの再利用 | 表 | `DataTable`、各グラフの「データテーブルを表示」 |

散布図はガイドブックの提供・推奨グラフに含まれないため、本テンプレートでは提供しない。

## グラフ設計の原則

**知りたいことを知れる**
- シンプルにする（冗長なデータ・装飾を取り除く）
- 意味のある順列にする（大小順・日付順）
- 強弱をつける（重要な系列だけ目立たせる）
- 待たせすぎない

**誤解を生まない**
- わかりやすく表記する（タイトルに「内容 + データ種別」。例: 「受付件数の月次推移」）
- データを定義する（対象、数値の意味、更新日）
- 表現を歪曲しない（**原点は 0**、軸範囲を恣意的に設定しない）
- メタ情報を記載する（出典、更新日、時点、注釈、免責）

## Do's / Don'ts

| Do | Don't |
| --- | --- |
| 全体の指標と詳細のグラフをセットで表示する | 指標だけ・詳細だけ |
| 色数を 1〜5 色に絞る | 系列ごとに多色 |
| 凡例をグラフに隣接させ、順序を対応させる | 凡例を離す、順序が違う |
| 棒グラフの原点を 0 にする | 軸を途中から始めて差を誇張する |
| 色以外（形・模様・ラベル）でも系列を識別できるようにする | 色だけで識別する |
| 不要なグリッド線・枠線を減らす | 3D、ドロップシャドウ、装飾 |

## 色

- データ可視化パレットは `src/tokens/theme.css` の `--color-chart-*`（ガイドブック Blue パレット由来）。
- グラフの色面と背景のコントラスト比は **3:1 以上**（Blue なら 500 より濃い）。満たせない色（`chart-seq-4` / `-5`）を使う場合は、色面のすぐ近くに数値（4.5:1 以上）を書くか、ホバー / フォーカスで数値を表示する。
- 増減は `trend-up`（青）/ `trend-down`（赤）に矢印と符号を併記する。

## アクセシビリティ

- グラフには代替テキスト（`role="img"` + `aria-label` の要約）を付ける。
- 同じデータを表（データテーブル）でも提供する。公開ダッシュボードでは CSV / Excel も公開する。
- 要約テキストを用意する。
