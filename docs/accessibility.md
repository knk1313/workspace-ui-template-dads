# スクリーンリーダーで画面の読み上げを確かめる方法

## 目的

画面を変えたあとに、スクリーンリーダーで主な操作を通し、読み上げの内容と順序が画面の見た目と合っているかを確かめる。自動の検査（axe、E2E、見た目の回帰テスト）では、読み上げの言い回しと、操作の流れが分かるかどうかは確かめられないため、この手順を人が行う。リリースの前と、部品の作りを変えたときに使う。

## 前提

- 手元で`npm run dev`を実行し、ブラウザーで`http://localhost:5173`を開いている
- macOSではVoiceOver（Safari）、WindowsではNVDA 2024.1以降（ChromeかEdge）を使える
- スクリーンリーダーの基本の操作（読み上げの開始と停止、見出しとランドマークの移動）を知っている
- 自動の検査（`npm run check`と`npm run test:e2e`）が通っている

## 手順

### 画面の構造

1. ダッシュボードを開き、スクリーンリーダーを起動する。
2. ランドマークの一覧を開き、「バナー」「ナビゲーション（メインナビゲーション）」「メイン」があることを確かめる。
3. 見出しの一覧を開き、h1が「ダッシュボード」の一つだけで、h2とh3が画面の区切りの順に並んでいることを確かめる。
4. ページの先頭でTabを押し、「本文へスキップ」が読み上げられることを確かめる。Enterを押し、本文の先頭へ移ることを確かめる。

### 一覧と削除

1. 申請一覧を開き、表の見出しが「受付番号・件名」「申請者」のように列ごとに読み上げられることを確かめる。
2. 「受付番号・件名」の見出しのボタンでEnterを押し、並べ替えの向き（昇順、降順）が読み上げられることを確かめる。
3. 1行目のチェックボックスを選び、「1件選択中」と一括操作のボタンが読み上げられることを確かめる。
4. 一括操作の「削除」を押し、「R08-001060を削除しました」と「元に戻す」のボタンが読み上げられることを確かめる。
5. そのままEnterを押し、「R08-001060を元に戻しました」が読み上げられ、行が一覧に戻ることを確かめる。

### フォームのエラー

1. 新規申請を開き、何も入力せずに「確認へ進む」を押す。
2. フォーカスがエラーのまとめの見出しに移り、「入力内容に6件の誤りがあります」が読み上げられることを確かめる。
3. まとめの中の「件名：件名を入力してください」のリンクでEnterを押し、件名の入力欄へ移ることを確かめる。
4. 件名の入力欄で、ラベル、「必須」、サポートテキスト、エラーの順に読み上げられることを確かめる。

### ダイアログと離脱の確認

1. 件名に文字を入力し、パンくずリストの「ホーム」を押す。
2. 「入力内容を破棄して移動する」のダイアログが開き、見出しと本文が読み上げられることを確かめる。
3. Tabを繰り返し押し、フォーカスがダイアログの中だけを回ることを確かめる。
4. Escを押し、ダイアログが閉じて「ホーム」のリンクへフォーカスが戻ることを確かめる。

### 結果の確認

次の二つを満たせば、確認は終わりである。

- 読み上げの内容が、画面に出ている文言と合っている
- 並べ替え、選択、削除、エラー、ダイアログの開閉の結果が、読み上げで分かる

合わない箇所があったときは、画面の名前と操作と読み上げられた内容を書いて、Issueに登録する。
